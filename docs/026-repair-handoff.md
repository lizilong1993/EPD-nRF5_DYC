# 给维修方：EPD 升级后快闪、无蓝牙广播

设备：7.5 寸 UC8179 黑白红屏，nRF52811，S112 7.3.0。2026-11-02 从可连接的 0x20 经 BLE DFU 传入自定义 0x26 后，LED 持续快速闪烁，手机与电脑均未再发现应用或 DfuTarg 广播。完全断电约30秒后重上电，75秒扫描仍无目标。

**请尽可能先读取现场，再恢复原厂固件。** 本次源码分析找到明确的广播配置缺陷，尚缺设备端数据来确认它是否为实际触发点。

优先检查：

1. 备份完整 Flash、UICR，记录实际芯片与 bootloader／SoftDevice／settings 布局。如果读保护阻止读回，请先记录，执行全片 recover／erase 会销毁现场。
2. 应用应为 52,984 字节，地址 `[0x19000,0x25ef8)`，SHA256：
   `e7f2c7c9e4d30724a0ea7f66f2485241ba36346b80f70dfda5282cbdcfa4312e`。
3. 只有确认应用一致后，使用附带 ELF 设置断点：
   - `0x1973e`：广播启动返回后，读取 R0。
   - `0x1ea48`：内部广告 configure 返回后，读取 R0。
   - `0x1fc30`：通用错误入口，读取 R0、LR 和调用栈。
4. 同时读取运行模式：本 ELF 的 RAM `0x200027fb`；Flash 记录位于 `0x27000`，mode 字节 `0x2700f`。记录 magic 应为 word `0x45504443`（小端字节 `43 44 50 45`），还需校验其它字段，不能仅凭单字节判断有效记录。

首要待确认链：新固件不迁移旧 FDS 配置，未读到有效新记录即默认日历模式。日历／时钟模式使用 Limited 标志 `0x05` 加无限广播时长 `0`，该组合不合法。广播配置若返回错误7，会经 APP_ERROR 立即复位；启动时100ms亮、100ms灭的动作发生在广播前，重复启动可表现为持续快闪。

**若 mode=1/2 且广播 configure 返回7，首要原因即可直接确认。若 mode=0，或者返回码不同，请按实际 PC／错误码继续查，不能套用上述结论。** 次要待查项是 SVCI 初始化失败后未恢复应用中断向量；可同时保存 RESETREAS、异常寄存器与 bootloader 实际内容。

请在取证后恢复维修方确认匹配本屏的原厂固件，并验证：启动广播、实际 GATT 连接、版本读取、断电后重连。没有广播不等于已证明主板损坏，也不能只凭 App “传输完成”认定新应用已经正常启动。

附件 `EPD-incident-evidence.zip` 是分析证据包，**不是 OTA 升级包**。其中交付过的0x26固件仅用于比对故障，请勿再次当作正常固件刷入。完整分析见 `026-incident-analysis.md`。
